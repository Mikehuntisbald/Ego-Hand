# v46 开发记录：固定速度、同步放宽加速度

目标：在 ±1.6 秒上下文和同一冻结 DiT 权重下，仅验证加速度约束×2。
速度保持 root=1.2m/s、手指相对腕部=.65m/s、腕部=5rad/s、关节=6rad/s。
加速度改为 root=24m/s²、手指相对腕部=20m/s²、腕部=60rad/s²、关节=80rad/s²。
优化归一化、提前惩罚和末端硬检查同步采用新值；选择器的速度/加速度代价保持原值。

遇到的问题与处理：
- 只放宽软约束会被旧硬上限重新收缩。统一通过 profile_config 配置求解和恢复步骤。
- 原入口输出 config 仍来自默认常量。入口覆盖为实际使用配置，并逐轨检查 limits 一致。
- 新片段库存不够原计划6个序列。按预先规定的元数据顺序选实际5个序列、10个未使用片段；不复用旧片段凑数。
- 旧数据中心筛选依赖GT是否可投影。新验证改为每5帧的检测观测、预测轨迹时序支持，取消GT中心门槛。
- 重新编码RGB容易改变精度/批形状。缓存保留BF16编码、16帧补齐；加上在线16帧对照检查。
- 侧别适配误用了RGB编码ROI（1.4倍、最小16px），与WiLoR原始ROI（1.3倍、最小24px）不同，27个观测侧别有差异。按原始重建输入重建侧别银行，重跑20个受影响轨迹，并逐轨检查种子侧别完全一致。
- 原最近帧采样允许边界容差，新片段时间戳波动使最远上下文达到1.602秒。按实际时间差屏蔽越界槽位，22段轨迹重跑；两版使用同一截断窗口。封装到v46入口，不修改已留档v44。
- 新片段演员与源序列以前出现过。只称新片段验证，WiLoR上游训练重叠未知。

验证：真实RGB运行16帧已通过；新入口与v45两种配置均完全一致（最大差0）。
新片段的两版共用一次生成的候选及路径，加入GT污染不变性检查；输出参数保存后重新解码检查。
冻结全部输出后评估准确率、快速动作幅度/方向、好点损坏、坏点恢复、伪跳变及骨长异常。
默认 CURRENT_PIPELINE 仍为 v42。本文件不是新片段通过验收的声明，最终指标见v46报告。

入口：complete_hand_tracks_acceleration_v46.py --input tracks.json --output result.json --profile acc_x2
实验：prepare_acceleration_validation_v46.py → run_acceleration_validation_v46.py（4个GPU分片）→ finalize_acceleration_validation_v46.py → evaluate_acceleration_validation_v46.py

最终结果（新片段，冻结后评估）：
- 10片段、5个已见过源序列、2个已见过受试者；1500帧、3760检测观测、130轨迹、662预测中心（560个GT关联有效中心）。
- 快动作幅度中位数57.91%→74.27%，方向保留53.56%→70.60%；逐点配对幅度增量的序列bootstrap95%区间为+10.60～+18.91个百分点。
- 中心相对误差30.107→28.634mm；相机误差40.387→40.557mm。两项配对置信区间均跨0，不能称明确准确率提升。
- 严格版原本≤10mm的3016点中42点变成>20mm；40061个原本>20mm点中3501点恢复到≤20mm（全有效观测点）。
- 原WiLoR相对误差>40mm的159中心：40.691→41.319mm，该组坏点恢复53→42。此分组不是遮挡真值。
- 两版均无伪跳变、骨长极值和骨长闪烁；全130轨迹的保存参数重解码和运动上限检查通过。默认v42未替换。
结论：加速度×2能减轻动作压缩，但高误差样本及少量好点仍有代价；适合作为保留动作的实验配置，继续保留人工复核。
